# 部署（T1 入口与数据分区配置）

> 上级：[README](../README.md) ｜ 前置约定：下文 `$AI` 指本仓根目录、`$BUILD` 指构建目录（解析规则见 README「构建」一节）｜ 相关：[本地屏](本地屏.md)、[测试](测试.md)

## 部署步骤

T1 入口是一张**普通 mini-ISO**：放数据分区（part1）根目录，**零 Ventoy 代码改动**即可从菜单启动。

```sh
$AI/pack/make_iso.sh             # 产物 $BUILD/test/0-OS-PILOT-AI.iso（约 52MB）
USB=/media/$USER/Ventoy          # 数据分区挂载点，按本机实际调整

mkdir -p $USB/ventoy                                     # ① 配置目录要自己建
cp $BUILD/test/0-OS-PILOT-AI.iso $USB/0-OS-PILOT-AI.iso  # ② 放入口 ISO

# ③ 选一种模型来源（都不配则 AI 启动后只能问答提示，不能工作）
sh $AI/tools/fetch_local_llm.sh $USB                     # A) 本地模型：一键下载 llama-server + GGUF 放盘
cp $AI/config/ai.json.example $USB/ventoy/ai.json        # B) 远程服务：改 base_url + model 为真实端点
```

> **`/ventoy` 要自己建**：Ventoy 安装器只把数据分区格式化成空盘，**不创建任何目录/文件**（VTOYEFI
> 分区里的同名 `ventoy/` 是引导资产，与数据分区无关）。数据分区 `/ventoy` 是 Ventoy 插件配置的约定
> 位置，也是本环境**识别数据分区的判据**——`mount_payload.sh` 只认含 `/ventoy` 的分区并挂到 `/iso`，
> 缺了它 AI 环境找不到盘。

数据分区上实际就这几样（其余文件随便放，互不影响）：

| 路径 | 谁准备 | agent 对它的操作 |
|------|--------|------------------|
| `0-OS-PILOT-AI.iso`（盘根） | 部署时放入 | 只读；`0-` 前缀让菜单排最前 |
| `/ventoy/ai.json` | 可选（本地/远程二选一） | 只读，拷进内存；缺失时自动回退本地模型 |
| `/ventoy/ai/models/*.gguf` | 本地模型方案：`tools/fetch_local_llm.sh` | 只读；存在则开机自动起本地 llama-server |
| `/ventoy/ai/llama-server` | 同上（或手动放入） | 只读；覆盖 ISO 内置的 llama-server（可换 v2/新版本） |
| `/ventoy/ai/llama-server.args` | 可选 | 只读；附加 llama-server 命令行参数（如 `-c 4096 -t 8`） |
| `/ventoy/ventoy.json` | 建议放入 | `schedule_boot` 调度时改写（先留 `.bak`），见下节 |
| `/ventoy/ai/logs/` | 运行时自动建 | 写日志：会话 `session-*.{jsonl,md}`、每次开机的 `boot-*.log`、启动即失败时的 `fatal-*.md`（见[出问题了看哪里](#出问题了看哪里)） |
| `/ventoy/ai/test_script.txt` | 可选 | 只读；有它则开机跑脚本模式（[测试](测试.md) 用） |

另外，`fs_write` 与 `gen_autoinstall` 工具会按需在数据分区写文件（如自动安装模板
`autoinstall-*.yaml`，覆盖前留 `.bak`）；能否写入、要不要确认由 `mode` 决定。

## 模型来源（本地 / 远程）

两种来源**任选其一**；同时配了也兼容——`ai.json` 里 `base_url` 非空即用远程，为空/无文件则回退本地。

**A) 本地模型（零配置默认路径）**：把 llama-server + GGUF 放数据分区，开机自动起服务。

```sh
sh $AI/tools/fetch_local_llm.sh $USB                  # 默认：llama-server.v3（AVX2）+ Qwen3.5-4B-Q4
sh $AI/tools/fetch_local_llm.sh $USB <模型文件名.gguf>  # 换其它 GGUF（手动放进 models/ 也行）
```

- 二进制查找顺序：`/iso/ventoy/ai/llama-server`（用户放入）→ ISO **内置**版本（v3/AVX2）→ 跳过并提示；
  无 AVX2 老 CPU 换 Release 里的 v2 变体放 `models/` 同级目录即生效
- 模型扫 `/ventoy/ai/models/*.gguf` 取排序**首个**；启动命令
  `--host 127.0.0.1 --port 8069 -c <按内存分档> --jinja`，需要调参用 `llama-server.args` 追加参数
  （追加在命令行最后，同参数后者生效，要固定窗口就写 `-c <N>`）
- 上下文窗口分档：`MemTotal ≥7000MB → 32768`、`≥5500MB → 16384`、其余 `8192`。
  本类模型为混合注意力（仅 8 层全注意力），KV 实测 32 KiB/token，三档分别占 256/512/1024 MiB
- agent 侧对 `system_probe` 输出有 12288 字节预算（实测 ~2.3 字节/token ⇒ 约 5.3k token，
  加系统提示与 11 个工具定义 3298 token 仍可进 8192 窗口）：超预算时先压挂载表/blkid/fdisk，
  再省略文件清单并留取回方式；同一份探测结果不会在上下文里出现第二次
- 资源：4B-Q4 级模型实测 RSS ~4.5GB、就绪 2s（KVM，冷启动）；建议机器 ≥8GB 内存。
  实测下限：QEMU `-m 4096`（guest MemTotal 3910MB）时模型加载直接失败
  （`llama_model_loader: failed to load model`），`-m 6144` 起可正常工作
- 就绪等待上限 240s，失败**不阻塞**启动——agent 会照常进入，问答时报连接错误
- `fetch_local_llm.sh` 支持断点续传、SHA256 校验、空间预检（+128MiB）；默认走 HuggingFace，
  国内可用 `VTOY_AI_LLM_MODEL_ENDPOINT=https://hf-mirror.com sh $AI/tools/fetch_local_llm.sh $USB`

**B) 远程服务**：拷 `config/ai.json.example` 到 `/ventoy/ai.json`，填 `base_url` + `model` 即可（见下节）。

## 配置（`/ventoy/ai.json`，可选）

样例见 [`config/ai.json.example`](../config/ai.json.example)。**用远程服务时**必需 `base_url` + `model`
（用本地模型时整份文件可省）；其余：`api_key`（空则回退环境变量 `VTOY_AI_API_KEY`，Ollama 等本地端点
可留空）`temperature` `max_tokens` `language` `http_proxy` `request_timeout` `payload_dir`（默认 `/iso`）
`log_dir`（默认 `<payload>/ventoy/ai/logs`）。https 端点可直连（CA 根证书已打进 initramfs）。

`base_url` 留空（或无 ai.json）时 agent 探测本地 8069 端口：就绪则接管，横幅模型名带**（本地）**标记，
`request_timeout` 低于 600 时自动提到 1800（CPU 推理慢）。

- `mode`：`readonly` 只读 / `orchestrate` 写操作需确认（默认）/ `direct` 直接执行
- 调试：`--no-reboot` 或 `VTOY_AI_NO_REBOOT=1` 时 `schedule_boot` 只写配置不重启

## 无人值守（`/ventoy/ventoy.json`）

```json
{
    "control": [
        { "VTOY_MENU_TIMEOUT": "10" },
        { "VTOY_DEFAULT_IMAGE": "/0-OS-PILOT-AI.iso" },
        { "VTOY_SECONDARY_BOOT_MENU": "0" }
    ]
}
```

`schedule_boot` 调度时**改写**它：`VTOY_DEFAULT_IMAGE` 改为目标系统镜像、`VTOY_MENU_TIMEOUT` 固定为
10 秒；带模板时一并写入 `auto_install` 段——下次开机即无人值守安装。其余键原样保留。

两条实测坑（Ventoy 1.1.05）：

- **`VTOY_SECONDARY_BOOT_MENU` 要显式设 `"0"`**：1.1.05 默认开启的「二级动作菜单」（Normal/grub2/
  memdisk/…）**没有倒计时**，会卡住无人值守启动。替代：设 `VTOY_SECONDARY_TIMEOUT`，或给文件名加
  `_vtnormal` 后缀。
- **`ventoy.json` 里不能出现负数**：Ventoy 的 JSON 解析器把 `-` 开头交给 `grub_strtoul`，解析失败会让
  **整份配置失效**。因此 `schedule_boot` 在 `timeout < 0` 时**省略该键**——Ventoy 插件内默认值即
  `-1`，语义等价。

## 真机注意

- **界面落在哪个 console**：agent 读写 `/dev/console`，由内核参数里**最后一个** `console=` 决定。默认
  命令行（`console=ttyS0,115200 console=tty0`）落在显示器；QEMU 无头抓用户态输出时，用
  `VTOY_AI_CMDLINE="console=tty0 console=ttyS0,115200 loglevel=3 rdinit=/init vtoy_ai=1"` 重新生成 ISO。
- **中文显示**：fbcon 没有 CJK 字形，agent 检测到显示器为前景控制台时**自绘屏幕**（接管 tty0 直画
  fb0，用随包的 Unifont 点阵字体）；`VTOY_AI_SCREEN=fb` 强制 / `tty`（或 `0`）禁用。详见[本地屏](本地屏.md)。
- **中文输入**：本地屏**已内置拼音输入法**（`Ctrl-Space` 切换中/英）；串口路径由宿主机输入法送 UTF-8 字节。
- **网络**：需要有**线网 + DHCP**（模块集覆盖常见有线/USB 网卡，**没有 WiFi**）。
- **显示**：真机 UEFI 下帧缓冲由内核内建 `simpledrm`（UEFI GOP）提供；未随包携带 GPU 驱动，legacy
  BIOS/CSM 老机器无 fb0 时回退文本控制台（中文受限，功能可用）。

## 出问题了看哪里

真机没有串口，`/tmp` 是 tmpfs（掉电即无），所以**盘上那份日志是唯一现场证据**。三种文件都在
数据分区 `/ventoy/ai/logs/`：

| 文件 | 谁写 | 什么时候有 | 里面有什么 |
|------|------|-----------|-----------|
| `boot-<UTC>.log` | init（PID 1） | 每次开机，只要数据分区挂上且可写 | 内核/命令行/CPU(含 avx2)/内存/`blkid`、块设备枚举、挂载结果、DHCP、**本地模型这一步的结论**、agent 退出码与其含义、退出前 `free`/`lsmod`/`dmesg` 末尾与 `llama-server.log` 末尾 |
| `session-<时间>.md` + `.jsonl` | agent | 会话建立之后 | 完整问答与工具调用；头部 `boot_log:` 指名同次开机的 boot 日志、`local_llm:` 是 init 的结论；结尾 `会话结束：rc=N` |
| `fatal-<时间>.md` | agent | **会话还没建立就退出**（配置/模型不可用） | 失败原因 + 环境自查（内存、`/iso` 挂载源）+ 那份 boot 日志的末尾若干行 |

- **"屏幕闪一下就关机"**：先看 `fatal-*`。它自带 boot 日志末尾，通常一眼定位——真机最常见的三种成因是
  盘上既无 `models/*.gguf` 又无 `ai.json`、CPU 不支持 AVX2（内置档为 x86-64-v3，需换 `llama-server.v2`）、
  内存不足被内核 OOM 杀掉（boot 日志末尾的 `dmesg` 与 `free` 会显示）。**若连 `fatal-*` 都没有**，
  多半是载荷盘没被认出来，见下面「`logs/` 空或整个 `ventoy/ai/` 都没被读到」。
- **失败不立刻断电**：`rc≠0` 且非脚本模式时，控制台打印结论 + 关键内存量后停留一段时间，按回车可进
  `busybox sh` 现场排查（`cat /iso/ventoy/ai/logs/boot-*.log`），`exit` 继续关机。停留多久取决于有没有
  盘上证据：**有** `boot-*.log` 时 10 秒；**本次没写出盘上日志**时 60 秒，并提示另插一支 U 盘、进 shell
  把 RAM 副本拷走（`mkdir /mnt/bak && mount -o fmask=0000,dmask=0000 /dev/sdXN /mnt/bak && cp /tmp/init.log /mnt/bak/`）
  ——真机掉电即失忆，这 60 秒是唯一取回现场的机会。
- **`logs/` 空或整个 `ventoy/ai/` 都没被读到**：多半是**载荷盘没认出来**。init 依次试挂所有分区（先分区、
  再无分区裸盘，排除 loop/ram/zram/光驱/dm-*），**只有**根下有 `ventoy/ai/` **或** `ventoy/ai.json` 的那块
  才算载荷盘。刻意不认"有 `ventoy/` 目录就行"：官方安装器在**每一支** Ventoy 盘上都建 `ventoy/`，装过
  Ventoy 的内置硬盘也一样——认它就把日志写进了没人会去看的盘里（表现正是"盘上找不到日志"）。真机上 U 盘
  要等 `usb-storage`/`uas` 加载 + 一次 SCSI 扫描才出现节点，内置盘却开机即在，所以挂载是**最多等 25 秒**的
  循环（每轮补一次 `mdev -s`）；要放大用 `VTOY_AI_PAYLOAD_WAIT=<秒>`（内核参数或同名环境变量）。到点仍没挂上
  时控制台会打印当时可见的块设备列表，把那一行贴回来就能定位。这种情况**盘上不会有任何日志**。
- **日志时间**：guest 无 NTP，文件名与内容按内核 UTC。若 RTC 被 Windows 按本地时间写入，会整体偏 8 小时
  ——boot 日志的「时钟:」行并列了三个原始值，判读时以它为准，别拿墙上的钟对。
- 数据分区挂上了但**只读**（NTFS 未清理、exFAT 脏位等）时 `mkdir logs` 会失败，控制台提示"不可写"、
  只留 RAM 副本；分区可写但**没有** `ventoy/ai/` 的盘不会被挂，见上一条。
