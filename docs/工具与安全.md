# 工具与安全

> 上级：[README](../README.md) ｜ 相关：[部署](部署.md)、[测试](测试.md)（工具链与磁盘工具的 guest 内实测）

| 工具 | 作用 | 限制 |
|------|------|------|
| `system_probe` | 内核/CPU/内存/网络/块设备/挂载点 + payload 文件清单 | 只读 |
| `fs_read` | 读文件或列目录 | 仅 `payload_dir` 内，单次 ≤1MB，二进制转 hexdump |
| `fs_write` | 写普通文件 | 仅 `payload_dir` 内；diff 预览 + 确认；原文件备份 `.bak`；原子写（tmp+rename） |
| `run_command` | 执行命令（无 shell） | 只读白名单直执（`find` 仅在不带 `-exec`/`-delete` 等参数时算只读）；其余需确认；shell 类命令（`sh`/`python`/`xargs`…）仅 `direct` 模式放行；命令名禁止路径分隔符 |
| `ask_user` | 向用户提问 | 脚本模式下返回"无法交互" |
| `schedule_boot` | 写 `ventoy.json`：`control.VTOY_DEFAULT_IMAGE` + `VTOY_MENU_TIMEOUT`，并按 `autosel` 挂自动安装模板（`timeout<0` 时省略该键 ⇒ 不显示模板菜单，Ventoy 插件默认即 -1） | 需输入 `REBOOT` 确认（direct 模式除外）；写前备份、写后重启 |
| `list_disks` | 枚举整盘/分区及结构化信息：容量、型号、总线、分区表、分区的文件系统/卷标/UUID/挂载点、`serial`/`wwid`；`protected=true` 表示禁止改动 | 只读 |
| `partition` | 对整盘重建分区表并创建分区（parted） | 只接受整盘；`protected` 设备一律拒绝；orchestrate 下需**逐字输入盘名**确认；parted 命令由本工具拼装（参数白名单）；`fs` 提示与 GPT 类型标志见[支持矩阵](#文件系统支持矩阵) |
| `format` | 在分区/裸盘上建文件系统 | 可建类型见[支持矩阵](#文件系统支持矩阵)（= 随包静态工具实际能建的类型，写进工具 schema 的 `enum`）；已挂载、承载 payload/根、整盘有分区的目标一律拒绝；orchestrate 下需逐字输入设备名确认 |
| `backup` | rsync 把 `src`（默认 payload_dir）内容同步到 `dst` | 拒写向承载 payload/根的盘（含同一物理盘）；`--delete` 要求 `dst` 是挂载点；确认后才执行 |
| `gen_autoinstall` | 确定性生成 Ubuntu autoinstall 应答脚本（cloud-config）：**选盘用磁盘序列号 serial、挂载用卷标 label**，字段符合 curtin schema（`disk` / `partition` / `format.volume` / `mount`） | 只写 `payload_dir` 内；目标盘必须是整盘且非 `protected`；镜像必须存在；diff 预览 + 确认 |

日志：每轮会话在 `log_dir` 生成 `session-<时间戳>.jsonl`（机器可读）与 `.md`（人可读，含工具调用与 diff）。

## 内置工具链（分区/格式化/备份）

initramfs 随包携带一套**全静态**工具（`pack/build_tools.sh` 构建，装到 `/bin` 以覆盖 busybox 同名
applet 的符号链接），`run_command` / `!命令` 可直接调用：

| 二进制 | 版本 | 说明 |
|--------|------|------|
| `mke2fs`（含 `mkfs.ext2/3/4` 别名） / `e2fsck`（含 `fsck.ext2/3/4` 别名） / `resize2fs` / `tune2fs` / `dumpe2fs` | e2fsprogs 1.47.0 | 建/查/扩/调参/导出 ext2-4；它的 libuuid 供 parted 静态链接，必须先编 |
| `parted` | GNU parted 3.6 | 建分区表与分区（编译时 `--disable-device-mapper --without-readline`） |
| `rsync` | 3.2.7 | 备份/同步（内置 popt/zlib，无 openssl/acl/xattr） |
| `mkfs.exfat` / `fsck.exfat` | exfatprogs 1.4.3 | exFAT 的建/检（关掉 blkid/uuid/selinux 等可选依赖，零外部链接） |
| `mkfs.f2fs` / `fsck.f2fs` | f2fs-tools 1.16.0 | f2FS 的建/检；上游 tarball 不含 `configure`，需宿主 `autoreconf -fi` |
| `mkntfs` / `ntfsfix` | ntfs-3g 2021.8.22 | NTFS 的建/修。**只取 ntfsprogs**（`--disable-ntfs-3g --enable-ntfsprogs`），挂载读写走内核 ntfs3，不引入 FUSE；同样需 `autoreconf -fi`，宿主缺 libgcrypt 开发件时由脚本内的桩宏顶上（探测只在 `--enable-crypto` 下真正执行） |

13 个二进制合计 17,400,784 B（≈16.6 MiB，未压缩）。initrd 实测增量：加 exFAT/f2FS 四个工具
+1,921,772 B、加 NTFS 两个工具 +1,007,873 B（gz 后约为原始体积的 43%）。`pack_env.sh` 找不到
`$BUILD/tools/` 时只警告（降级为 busybox 自带 applet），并逐个报告缺失的工具名。安装到 `/bin`
而非 `/sbin`（`run_command` 的 `PATH=/bin:/sbin:...` 让 `/bin` 优先），且必须先 `rm` 再 `cp`
（否则 `cp` 会穿透 busybox 的符号链接写到本体）。

## 文件系统支持矩阵

对外类型名一律与 busybox `blkid` 报出的名字一致，这样 `format` 之后回读的 `TYPE=` 能直接与请求
比对。**新增一种格式 = 在 `agent/internal/disk/ops.go` 的 `fsSpecs` 里加一项**，工具描述、报错文案、
GPT 类型推导都从这张表生成，不存在第二份清单。

| 类型 | 挂载读写 | 创建 | 检查/修复 | parted 记号 | GPT 类型 | 卷标上限 | 典型归属 |
|------|----------|------|-----------|-------------|----------|----------|----------|
| `ext2`/`ext3`/`ext4` | ✅ | ✅ `mke2fs` | ✅ `e2fsck` | 同名 | Linux FS | 16 | Linux 装机目标 |
| `vfat`（FAT32） | ✅ | ✅ `mkfs.vfat` | ❌ 未随包 `fsck.vfat` | `fat32` | ESP（保留 esp 属性） | 11 | 所有平台的 ESP |
| `exfat` | ✅ | ✅ `mkfs.exfat` | ✅ `fsck.exfat` | **无此记号** ⇒ `mkpart` 省略 | `set N msftdata on` | 15 | Windows + macOS + Android 13+ 通用数据盘 |
| `ntfs` | ✅ 内核 ntfs3 | ✅ `mkntfs -f -F` | ✅ `ntfsfix` | `ntfs` | `set N msftdata on` | 16 | Windows 数据盘 |
| `f2fs` | ✅ | ✅ `mkfs.f2fs` | ✅ `fsck.f2fs` | `f2fs` | Linux FS | 16 | Android 内部存储 / OTG |
| `xfs` | ✅ | ❌ xfsprogs 未随包 | ❌ | `xfs` | Linux FS | 16 | Linux（装机由安装器自建） |
| `hfsplus` | ✅ | ❌ **Linux 端无 mkfs**（`mkhfsplus` 属 Darwin） | ❌ hfsprogs 未随包 | `hfs+` | Linux FS | 16 | macOS 旧格式盘（只读写、不重建） |
| `apfs` / `refs` | ❌ | ❌ | ❌ | ❌ | ❌ | — | **不支持**：APFS 无开源实现、ReFS 本内核无模块 |

- **跨平台数据盘（Win + Mac + 手机都读写）的答案是 exFAT**；Mac 的新格式 APFS 与 Windows 的 ReFS
  在 Linux 端都没有可用的创建工具，遇到只能读写挂载或引导用户改用 exFAT，不能承诺格式化。
- `mkntfs` 必须带 `-f`：不带它会把整个卷逐簇写零（实测 1GiB 4.29s ⇒ 1TB 约 70 分钟），而工具链里
  其它 mkfs 都只写结构、不清零。
- `ext4` 必须带 `-O ^orphan_file,^metadata_csum_seed`：随包 e2fsprogs 1.47 默认开这两个特性，
  目标发行版（Ubuntu 22.04 的 e2fsck 1.46.5 / GRUB 2.06）读不了，表现为 `grub-install` 报
  "unknown filesystem"、装完开机进紧急模式。
- **可格式化清单来自运行时探测**：`fsSpec` 里的 mkfs 二进制在 `PATH`（与执行时同一份，
  `VTOY_AI_TOOL_PATH` 可覆盖）里存在才写进 `format` 工具 schema 的 `enum`。所以某类工具没随包时，
  模型看到的契约里就没有这个类型（`hfsplus`/`xfs` 永远不进 `enum`），不会"先承诺再在执行时失败"。
- `fsck.exfat` / `fsck.f2fs` / `ntfsfix` **不做成 agent 工具**：那会开出第二条绕过 `format` 逐字确认
  闸门的写路径。它们只出现在本文件、执行失败时的提示文案和 `pack/verify_tools.sh` 里，用户在命令
  模式自行执行（orchestrate 下走确认）。

## 磁盘工具的三层防护

1. **硬守卫（任何模式都生效）**：承载 payload（`/iso`）与根文件系统的设备、已挂载的设备、以及"其上有
   分区被挂载"的整盘，一律拒绝改分区/格式化；`backup` 拒绝写向承载 payload/根的盘（含同一物理盘）。
   `List` 的 `protected` 标记与写守卫共用同一份 `protectionOf`，不会漂移。
2. **参数白名单**：所有写操作的 argv 由 `agent/internal/disk/` 拼装，用户字符串只允许落在白名单内
   （设备路径 `devRe`、卷标 `labelRe`（≤16 字符，再按类型收紧）、分区名、大小 `sizeRe`、分区表
   只允许 gpt/msdos），文件系统必须是 `fsSpecs` 的键且随包工具确实在场；一律
   `exec.Command(argv)` 裸名执行、不经 shell、`PATH` 固定，因此无法注入元字符或自定义危险开关，
   新增文件系统类型也只是加一张表的表项，不扩大任何注入面。
3. **交互确认**：`orchestrate`（默认）下 `partition`/`format` 要求**逐字输入目标设备名**（如 `vdb`），
   `backup` 要求 y/N（带 `--delete` 时同样逐字确认）；`direct` 模式视为已授权、跳过确认；`readonly`
   直接拒绝。确认前会先展示将执行的确切命令（`steps`）。

容量与对齐：分区从 1MiB 起、按 MiB 向上取整，`size` 支持 `100MiB`/`8G`/`rest`（`rest` 只能放最后）。
`partition` 的 `fs` 只是 parted 的类型提示（按[支持矩阵](#文件系统支持矩阵)映射，`vfat`→`fat32`、
`hfsplus`→`hfs+`、`exfat` 无记号则省略）；GPT 上 `msftdata` 只在 parted 给不出记号（exfat）或该格式
本就该让 Windows 认作基本数据盘（ntfs）时补，Linux 侧类型（ext*/xfs/f2fs/hfs+）不加——加了会让 Windows
提示格式化。卷标上限按类型收紧（vfat 11、exfat 15、其余 16）。`format` 能建哪些类型见矩阵（由随包工具
决定，运行时探测）。`gen_autoinstall` 的模板类型与 `fsSpecs` **刻意解耦**：那串由 Ubuntu curtin 解释，
只出 ext2/3/4/vfat，否则模型会以为能用 exFAT 装系统。模板生成用 `serial` 选盘、用卷标挂载（curtin 的
`disk` 没有 UUID 匹配——空盘在选盘时还没有文件系统；UUID 用在装完后的 fstab）。
